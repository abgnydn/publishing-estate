# Incident → mechanism

Every mechanism in this repository was added after something went wrong. This
is the list, oldest failure class first. Nothing here was designed in advance.

**This page quotes retracted numbers.** Every figure below that is marked
retracted, withdrawn or wrong is quoted as an example of a defect, never as a
claim. It is the one piece of prose in this repository allowed to carry them,
and the withdrawn-value sweep treats a number sitting next to the word
"retracted" as disclosed rather than live. That distinction is itself one of
the mechanisms.

Further occurrences exist by construction, and the sweep classifies each as
DISCLOSED rather than LIVE. `facts/facts.json` holds a `withdrawn` entry with
its value intact, because recording that a value is retired is what the entry
is for. `render/sites.source.withdrawn.json` names that entry by id so the gate
can be watched refusing it. `README.md` quotes the gate's refusal verbatim, and
that quoted line carries the id. `checkers/fixtures/notes/zerotvm.md` plants
the value twice — once bare and once inside its own retraction — so
`check-memory.mjs` can be watched firing on the first and staying quiet on the
second. `checkers/README.md` quotes that fixture — both the bare line and the
checker's finding on it — inside the same demonstration. None of these asserts
the number. Everywhere else in this repository a withdrawn value is a defect.
The sweep that classifies these — like the social-card sweep and the DOI
checker in three rows below — runs on the author's machine and is not in this
repository; the rows record the incidents that shaped it.

| what happened | what now exists |
|---|---|
| **Three generations of one data file live at once.** Every site rendered its sibling cards from a copy of the generated site data, baked in at deploy time and never regenerated. One site said the flagship ran at ~40 tok/s and was "22% behind WebLLM"; the flagship's own copy said 69.6 tok/s and "+16%"; the benchmark artifact said 69.55 and +16.0%. The *sign* of the project's founding comparison was inverted on a live page, and had been for weeks. | `facts/facts.json` plus placeholder-only rendering. A number reaches a public surface only through a `{{fact:id}}` placeholder resolved at build time from one registry. There is no path for a hand-typed number into a stat tile, and a consuming copy is regenerated rather than edited. |
| **The same quantity published at five different values.** A shader count appeared as 18 in a README, 27 in the generated data and on three live pages, 42 on the project's own site, and 55 in the agent instructions. Only one of the five was produced by running anything. A device count was simultaneously published as 592, 92, 890 and 119 — all retracted now except the last, which is the only one with a recorded query. | Registry rule 1: no number on any public surface without an id here. Rule 2: `produced_by` must be a command that can be RUN, or the status is `unbacked` and the number may not appear in a headline, tagline or stat tile. |
| **A tally passed the protocol check into a tagline, then moved within a day.** The shader count was corrected to a produced, protocol-status value — and then went 50 → 51 the next day, because it counts something that grows. Chasing a growing count buys one day and leaves the trap armed. | `kind: "tally"`. The render gate refuses a tally in any headline context regardless of status. A tally may appear only on the surface that generates it. A sentence without a number cannot go stale. |
| **A retracted average survived on five surfaces, once as "2,865×".** The value 2865 was withdrawn and superseded by medians, but it lived on in a stale baked copy and on one live page comma-grouped, which a bare grep for `2865` never matched. | The withdrawn sweep generates thousands-separated and unit-formed variants of every withdrawn value, and classifies a hit as DISCLOSED rather than LIVE when the surrounding text is retracting the number rather than asserting it. |
| **A withdrawn number hid in a social-card image no grep reads.** A rendered `og.png` said "Measured on 92 devices" — a retracted count, invisible to every text sweep, and the image is what every link preview shows. | The sweep covers each surface's `og.svg` source, and separately reports an `og.png` older than its `og.svg`: the state in which a number corrected in the source keeps shipping as pixels. |
| **A verification sweep passed while completely broken.** An unquoted shell variable fed the search tool one bogus path; it errored into `/dev/null` and reported "0 hits" for every stale pattern, including strings that were definitely present. The run looked identical to a clean one. | Positive controls in every sweep, and `--selftest` on every checker, run before the sweep in the same process. `facts/check-facts.mjs` plants a mismatch, a match and a failing command through the same comparison function the real facts use, and exits 2 if any of the three is misread. |
| **A prose `produced_by` reached the shell and executed.** The runnable predicate was "does not start with UNRESOLVED" — a naming convention doing execution-guard work. A supervisor planted the string `measured by hand $(touch SENTINEL) on the M2 Max`; the cheap-verify pass shelled it out, the `$(touch)` ran, and the failure surfaced as a benign UNREACHABLE with exit 0. | A command-shape allowlist. `produced_by` reaches `execSync` only if it starts with one of the commands the registry actually uses. Extend the allowlist deliberately when a new fact needs a new tool, never by loosening the pattern. |
| **Two verifier verdicts arrived after the comment was live.** A draft that had already survived one authoring pass and four adversarial review agents still told readers to upgrade to a version that cannot load the model it recommended. A fifth agent found it by creating a session against the real build and watching it fail — 34 minutes after posting. Everyone subscribed had already been emailed. | The sha256 ledger and the publish gate. Approvals bind to the exact bytes reviewed and expire the moment the file is edited. A lens writes its entry as the last step of its review, before it reports back; until the entry exists, the publish stays blocked. |
| **Counting agreeing reviewers turned out to measure very little.** Four lenses from one model family carry roughly 1.7 effective votes (a Kish-formula derivation from arXiv 2605.29800's reported correlations, not a figure the paper states). A SAFE verdict is absence of evidence from a judge whose measured defect recall is poor. | The quorum requires at least one ANCHORED SAFE — a verdict whose note cites execution output, a fetched primary source, or a file:line. Reading-only agreement, however unanimous, does not clear the gate. Any DO-NOT-POST still vetoes outright. |
| **The gate had never been fuzzed, and 8 bypasses took under an hour to find.** The override flag was matched as a substring of the whole command, so the literal string `CLAUDE_PUBLISH_VERIFIED=1` quoted inside untrusted content a lens was reviewing self-authorized the gate. The `/markdown` read-only exemption was also a whole-command substring, so any publish whose *body* mentioned it was exempt. `gh api -f` auto-switches to POST and was unmatched. An assertion with no artifact was allowed with a warning, which made the ledger optional. The ledger scan spawned three processes per entry and would have exceeded the harness timeout past ~580 entries — and a timed-out hook does not block, so the gate would have silently disabled itself as the ledger grew. | Anchored override prefix (both variables, at the START of the command); endpoint-position-only exemption; no assertion-only path; auto-POST, repo-write, curl, gh-pages and matcher-evasion triggers added; single-pass ledger scan. Each is a case in `test/hook-test.sh`, written fail-first. **Run the adversarial audit on the guards themselves, periodically.** |
| **MCP write tools published without touching Bash at all.** The gate matched on shell commands. A GitHub MCP server exposes `create_pull_request`, `add_issue_comment` and `issue_write` as tool calls that never produce a command line. | MCP write tools are denied at the hook and routed to the CLI, where the ledger flow applies. They have no override path by design. Reads pass through. |
| **A caveat was written down and never travelled.** A model card published a block cosine of 0.936 as evidence that 3-bit experts were usable, while the repo's own spec file argued at length that the number could not support that claim — a fidelity metric does not predict output quality, and the counterexample was in the same codebase. The number was accurate. The inference built on it was wrong. That value is withdrawn. | `caveat` is a field that travels to the surface with the value; `note` is for whoever maintains the registry. A `single-run` or `provisional` fact must carry one, and the render gate refuses to render it bare — the source must write `{{fact:id+caveat}}`. On a `protocol` fact the caveat is optional context, because caveating everything teaches readers to skip caveats. |
| **A profile page carried four wrong descriptions at once.** A product credited with an SDK, a Web Component and an MCP integration its own repo records as deleted. A project called finished whose README opens "Not a finished product". A trainer credited with GPU AdamW that runs Adam in JavaScript on the CPU. A tool said to sandbox scripts whose README says it "does not replace runtime sandboxing". Every one of those repos stated its own limits clearly. Nobody reread them. | The `claim-auditor` lens: compare a description to the thing described, atomic claim by atomic claim, with the source that settles each one. The repo wins. A description vaguer than the repo is fine; a description stronger than the repo is the defect. |
| **The site quoted paper figures its own errata had retired.** A concept DOI always resolves to a paper's current version, so a revision that retires a figure expires every citing surface with no visible change anywhere. Six stale *version* DOIs across four files separately pinned a preprint six revisions behind. | The DOI checker remembers what each concept DOI resolved to last run and reports PAPER-MOVED as a delta, with the list of surfaces that cite it. Version pins where a concept DOI belongs are a separate finding. |
| **A fix sat committed but undeployed for weeks while production served the bug.** Git was clean. The live surface was not. | A deploy is not done until the live surface passes the sweep. Liveness checking is part of the deploy path, not a separate cron job. `checkers/check-deployed.mjs` is the machine form: take sentinels from the built output and ask whether the live url still contains them, because "commits ahead of the remote" is a proxy that misses the worse case — committed, pushed, and still never deployed. |
| **Per-platform posting rules lived as prose inside one agent definition.** At one platform that is fine. At six it becomes six drifting copies of one checklist, which is the bug the registry was built to kill. | `lenses/platforms.json`: rules with a source and a date, per platform, read by the agents. No platform rule is hardcoded in a lens. Where a platform's state is unknown it says `unaudited`, because an invented rule is worse than a recorded gap. |
| **The personal site's source was lost.** A direct-upload project whose folder was never committed. | Rebuilt from the deployed bytes. Everything has a remote now, and the registry lives in git rather than in a home directory — losing it again is the failure mode the design is against. |
| **The numbers nobody had registered were the ones that were wrong** (2026-08). The drift sweep re-reads numbers that already have an id, so it is structurally blind to a number nobody wrote down: an unregistered number cannot drift, so it is never reported. Every defect found in one afternoon's manual read of the profile surfaces was of exactly that kind, and every one was found by a person happening to look. | `checkers/check-orphans.mjs`: sweep every surface, report every claim-shaped number with no id, and rank rather than filter so nothing is silently dropped. Holding every number from every surface at once also answers the question the registry cannot — is one quantity published at two different values across two surfaces. |
| **The prose notes a session reads back were the only surface nothing audited** (2026-08). They are written once, in the tense of the day they were written, and then quoted back as current. One asserted a repository was "sitting 7 commits unpushed" — true when written, a claim about right now when read. | `checkers/check-memory.mjs`: a withdrawn value repeated, a number disagreeing with its own project's registry entry, and a claim git can answer right now and answers differently. Retraction language in the sentence suppresses the first, because a note recording that a number was retired is doing its job. |
| **A deploy raced the tests it was meant to wait for, and a missing secret made it succeed having done nothing** (2026-08). The deploy workflow triggered on push to main with no `needs:` and no `workflow_run`, so it could land while the tests were still running, or after they failed. Its deploy step exited 0 with a notice when its token was unset. Separately, one repository's CI had failed four of its last five runs unnoticed, and the verification system itself had no CI at all. | `checkers/check-ci.mjs`: standards locally — is there a pipeline, is the deploy downstream of the tests, does a step report success having skipped — and health over the API: did it run, was it green, and was it green on the code that is in the tree now. A rate limit is UNREACHABLE, never a repository with no runs. |
| **Nothing answered "is any of this landing"** (2026-08). Every check asked whether a published number was wrong. The record already held the shape of the problem — the preprints travelled while the runnable software records sat in single digits — and the asymmetry stayed invisible until someone went looking. | `checkers/check-reach.mjs`: read the public counters for the archival records, the repositories and the model hub. A source that did not answer is UNREACHABLE and never a zero, because a missing number and a real zero mean opposite things here, and conflating them makes a quiet week look like a dead project. |
| **A lens-name typo counted as a second distinct reviewer** (2026-08). The gate counts distinct lens names. The ledger held both `claims` and `claim-auditor`, and both `rendering` and `rendering and mechanics`. One review satisfied a two-review quorum. | The gate normalises lens names before it counts anything, and `checkers/check-lenses.mjs` reads the ledger as a surface: names outside the canonical set, quorums that hold only before normalisation, lenses run one at a time when they are independent by construction, and SAFE verdicts carrying no evidence at all. |
| **Three checkers ran with a flag that silenced their findings, and one had never successfully reported at all** (2026-08). `--quiet` was meant to mean "findings only" and was routing findings through the suppressed channel, so those checkers exited non-zero with empty output. One checker had not reported successfully in any scheduled sweep, and nothing noticed, because a broken sweep and a clean one produce the same output. | The fault case, required in every selftest. A missing config, a malformed config, a config naming nothing to check, an unreadable ledger entry and an unreadable workflow file each hard-fail rather than produce a clean sheet. A finding never travels through an optional output channel. |
| **The publish gate did not cover the model hub, and the regex meant to cover it could never match anything** (2026-08). Only the `--create-pr` form and the old CLI were gated, so the safer shape — a reviewable pull request — was blocked while a direct write to main was not, and a push to a Space repository was not covered at all. The git-push matcher that should have closed the gap — in the author's installed hook; this repository's own history carried no git-push matcher at all — had a `\\.` inside a single-quoted bash regex; bash performs no escape processing there, so grep received backslash-backslash-dot and matched a literal backslash. Separately, the curl matchers required the write flag to appear after the host, so the same command with its arguments in the other order passed. | Upload, repo-write, CLI, git-push and curl forms all matched; both argument orders matched; every form is a regression test in `test/hook-test.sh`, each confirmed to pass the previous hook before the fix landed. |
| **A ledger entry proved that something had been reviewed and never what** (2026-08). Entries are keyed by sha256 alone. Once the artifact file changed, moved, or the scratch directory holding it was deleted, nothing could reconstruct the bytes a lens had actually read. | `gate/dry-run.mjs --archive` copies the verified bytes to `<sha256>.body` beside the entry, and refuses to write a body whose hash is not the name it would be stored under — so a drifted file cannot quietly become the record of what was approved. |
| **The only way to learn the gate's verdict was to attempt the publish** (2026-08). A bad way to ask a question whose wrong answer is a notification that has already been emailed to everyone subscribed to the thread. | `gate/dry-run.mjs` reads the ledger and prints the verdict the hook would reach, in the hook's own order of precedence, and can approve nothing. `test/dry-run-agrees.sh` puts the same ledger states to both and fails on any disagreement, because a readout that has drifted from the rule it claims to read out is worse than no readout. |
| **Review lenses ran at whatever model and reasoning effort the spawning session happened to be using** (2026-08). Two runs of nominally the same quorum were therefore not the same quorum, and nothing on the ledger entry recorded which had happened. | `docs/tiers.md`: three capacity tiers for pipeline agents, start at the lowest that can do the job, escalate only on a specific demonstrated failure. Lenses are the exception and declare model and effort in their own frontmatter, so quorum quality cannot degrade because of an ambient setting somewhere else. |

## What the list is for

Two things.

First, every rule in this system is traceable to a line in this table. If you
adopt a mechanism, adopt it because you recognise the incident, not because it
is here. A rule with no incident behind it is a guess, and guesses about your
own failure modes are usually wrong in the flattering direction.

Second, the shape of the list is itself a finding. Read the "what happened"
column and count how many are *a correct thing that stopped being correct*
rather than *a mistake made at the time of writing*. The count is most of them.
Publishing systems are usually built to catch errors at authoring time. Almost
nothing here failed at authoring time.
